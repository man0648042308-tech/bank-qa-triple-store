# 从零复现操作手册

> 2026-09-04本机已经由AI跑通；最新命令结果见`evidence/验收记录.md`，不要为复习重复创建环境。当前vmrun的Tools取IP路径异常，运行01/02/03/04/06脚本时加`-VmIp 192.168.220.77`，脚本会验证远端UUID对应精确VMX；地址不符则停止，不能盲改成其他IP。以后VM地址变化需要重新核验。离线阶段无需三库；在线阶段使用本机SSH隧道。新增在线固定问答复核命令：`uv run --offline --no-sync python tests\verify_online_evaluation.py`，预期`ONLINE_EVALUATION_PASS cases=4`。

本手册默认你使用：Windows 11、VS Code、PowerShell、`uv`，数据库运行在 VMware Ubuntu 的 Docker 中。第一次严格按顺序执行，不要同时在Windows Docker和虚拟机Docker各启动一套。

## 0. 先认识三个“位置”

| 位置 | 用什么操作 | 放什么 |
|---|---|---|
| Windows项目目录 | VS Code + PowerShell | Python源码、测试、文档、脚本 |
| VMware Ubuntu | SSH和Docker | ES、Redis、Neo4j容器 |
| Windows本地SSH隧道 | `scripts/06`与`07` | 把`127.0.0.1`四个本地端口转发到VM回环服务 |
| 浏览器 | Edge/Chrome | FastAPI `/docs`、Neo4j页面 |

项目绝对路径：

```text
./Day37_Bank_QA_Homework
```

虚拟机部署路径由脚本限定为：

```text
/opt/day37-bank-qa
```

本项目不要求Windows Docker Desktop运行。若Docker Desktop处于停止状态，不必为本作业启动它。

安全数据流是：

```text
Windows Python → 127.0.0.1本地端口 → SSH加密隧道 → VM 127.0.0.1 → Docker数据库
```

数据库端口不允许绑定VM的`0.0.0.0`，也不允许Windows应用直接使用VM IP连接。

### 5.2 运行只读检查

回到VS Code PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\scripts\01_检查VM.ps1"
```

解释：

- `powershell`：启动一个PowerShell子进程执行脚本。
- `-ExecutionPolicy Bypass`：仅为这一次子进程绕过本机脚本执行限制，不永久更改系统策略。
- `-File`：后面是要执行的脚本文件。
- `.\`：从当前项目目录开始找。

这个脚本会：发现当前VM IP；检查22端口；用现有SSH密钥连接；验证Docker Server；列出容器、镜像缓存和端口。它不会启动或删除资源。

若显示“指定的Day37虚拟机文件不存在”或“精确虚拟机未运行”，先回到VMware核对上面的`.vmx`绝对路径和开机状态，不要改脚本去连接一台身份未知的主机。

2026-09-04现场发现：SSH已通、来宾open-vm-tools运行，但宿主vmrun仍报告Tools未运行。此时可以显式传入已知IP：

```powershell
powershell -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\scripts\01_检查VM.ps1" -VmIp "192.168.220.77"
```

`-VmIp`是脚本参数名，后面是本次已核验的地址。脚本仍先检查精确VMX在运行，然后使用SSH严格主机指纹校验，并比较来宾DMI UUID与VMX的BIOS UUID；不一致立即停止。不会扫描网段或自动改连别的主机。此情况下后续02、03、04、05、06脚本同样带上 `-VmIp "192.168.220.77"`。IP变化后需要先核对新地址，不能照抄旧IP当作已验证事实。

成功标记：

```text
DAY37_VM_CHECK_PASS
VM_IP=实际地址
```

把`VM_IP=...`抄进实验记录，是为了证明脚本检查了哪一台VM；**不要**把该IP填入Python服务地址，也不要设置`VM_HOST`让应用直连VM。后续脚本会根据已核验的VM身份建立SSH隧道，Python始终连接Windows本机`127.0.0.1`。

## 13. FastAPI加分入口

### 13.1 离线API

```powershell
$env:DAY37_API_KEY = Read-Host "请为本次PowerShell输入临时API Key"
$env:DAY37_MODE = "offline"
```

逐行解释：

- `$env:DAY37_API_KEY`：只给当前PowerShell进程设置服务端密钥；关闭该终端后失效。
- `Read-Host`：在终端交互输入，不把真实值写入源码、Markdown、命令历史示例或`.env`。
- `$env:DAY37_MODE = "offline"`：让API使用内存替身，便于先验证业务和鉴权。
- `uvicorn day37_bank_qa.api:app`：从`api.py`加载名为`app`的FastAPI对象。
- `--host 127.0.0.1`：API只监听本机回环地址，不对局域网暴露。
- `--port 8000`：监听本机8000端口。

终端保持运行。可以浏览代码生成的接口说明：

```text
http://127.0.0.1:8000/docs
```

然后打开**第二个PowerShell终端**，切换到项目目录，并让客户端使用与服务端相同的当前会话密钥。若两个终端不是父子进程，第二个终端需要你再次输入相同临时值：

```powershell
Set-Location "./Day37_Bank_QA_Homework"
$env:DAY37_API_KEY = Read-Host "请输入与服务端相同的临时API Key"
$headers = @{ "X-API-Key" = $env:DAY37_API_KEY }
```

`@{ ... }`是PowerShell哈希表；这里表示HTTP请求头名`X-API-Key`对应当前环境变量中的值。依次验证三个业务端点：

```powershell
Invoke-RestMethod -Method Get -Uri "http://127.0.0.1:8000/health" -Headers $headers
Invoke-RestMethod -Method Get -Uri "http://127.0.0.1:8000/products/search?keyword=phone&min_price=100.5&max_price=800.75" -Headers $headers
$body = @{ customer_id = "C001"; question = "我有5000元，请推荐稳健产品"; top_k = 3 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/qa/ask" -Headers $headers -ContentType "application/json" -Body $body
```

关键字解释：

- `Invoke-RestMethod`：PowerShell发送HTTP请求并把JSON响应转换成对象。
- `-Method`：HTTP动作，读取用`Get`，提交问答用`Post`。
- `-Headers $headers`：携带API密钥请求头；三个端点都必须带。
- `ConvertTo-Json`：把PowerShell哈希表转换为JSON请求体。
- `-ContentType "application/json"`：告诉服务器请求体格式是JSON。

鉴权预期：

- 服务端没有设置`DAY37_API_KEY`：返回503，表示服务配置不完整；
- 请求缺少或使用错误的`X-API-Key`：返回401；
- 服务端已设置且请求头正确：返回200和业务JSON。

真实密钥绝不能写进项目。教程中的“临时API Key”只是提示文字，不是密钥值。

业务上依次观察：

- `GET /health`
- `GET /products/search`
- `POST /qa/ask`

结束时在终端按`Ctrl+C`。

### 13.2 在线API

确认真实集成验证全部通过后，在新PowerShell设置：

```powershell
$env:DAY37_API_KEY = Read-Host "请为本次PowerShell输入临时API Key"
$env:DAY37_MODE = "online"
uv run uvicorn day37_bank_qa.api:app --host 127.0.0.1 --port 8000
```

在线API仍连接`127.0.0.1`的SSH隧道端口。不要设置VM IP直连。如果当前教学部署关闭Neo4j认证，不要编造或保存密码；客户端配置必须与实际部署方式一致。

## 14. 停止Day37服务

完成实验后：

```powershell
powershell -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\scripts\07_停止SSH隧道.ps1"
powershell -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\scripts\05_停止Day37.ps1"
```

成功标记：

```text
DAY37_SSH_TUNNEL_STOP_PASS（或已停止时DAY37_SSH_TUNNEL_ALREADY_STOPPED）
DAY37_STOP_PASS（只停止，未删除）
```

先停止Windows本地SSH隧道，再停止VM中的Day37容器。`07`会校验进程身份，只停止自己创建的SSH进程；`05`使用`docker compose stop`，只停止三个Day37容器并保留网络、卷和数据。不要自行添加`-v`。

第二天重新开始时运行：

```powershell
powershell -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\scripts\02_部署Day37.ps1"
```

`02`会再次启动隧道和健康检查；若容器已经在运行、你只需要重建隧道，则单独运行`06_启动SSH隧道.ps1`。

## 15. 怎样保存Typora作业

1. 用Typora打开：

```text
./Day37_Bank_QA_Homework\Day37作业_提交版.md
```

2. 阅读并确认没有把AI验收写成个人掌握。
3. 按`Ctrl+S`保存Markdown。
4. 在最终测试和真实联调通过后，选择“文件 → 导出 → PDF”。
5. 输出到：

```text
./Day37_Bank_QA_Homework\output\Day37作业_提交版.pdf
```

6. 打开PDF逐页检查中文、代码块、表格和分页。只有文件确实存在且逐页复核后，才在提交清单中把PDF标为“已完成”；当前Markdown教程本身不代表PDF已经生成。

## 16. 第一次复现不要跳过的记录

在自己的学习笔记中填写：

```markdown
- 日期：
- 我亲自运行的命令：
- 测试结果：
- 第一次缓存是hit还是miss：
- 第二次缓存是hit还是miss：
- 我遇到的原始错误：
- Traceback最后一行：
- 我怎样定位：
- 我现在能独立解释的3件事：
- 我仍不能独立完成的1件事：
```

没有亲自运行时写“未开始/无提交证据”。即使最终验收阶段生成了`evidence/验收记录.md`、PDF或ZIP，它们也只能证明工程或提交包被验证，不证明你已掌握。能脱离答案重写、制造并修复错误、解释Traceback，才是个人能力证据。
