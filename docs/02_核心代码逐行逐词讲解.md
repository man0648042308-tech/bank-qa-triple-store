# 核心代码逐行逐词讲解

本章不是让你背代码，而是回答四个问题：数据从哪里来、每行拿到什么、怎样变形、最后交给谁。先看全局，再拆语法。

## 2. `import`到底做什么

实际代码：

```python
from dataclasses import dataclass
from typing import Any
```

逐词解释：

- `from`：从某个模块中取名字。
- `dataclasses`：Python标准库模块名。
- `import`：把后面的名字引入当前文件。
- `dataclass`：被引入的装饰器，帮助生成初始化、显示、比较等代码。
- `typing`：类型工具模块。
- `Any`：表示这里允许任意类型；它是类型提示，不会自动检查运行值。

下面两种写法都能导入，但调用方式不同：

```python
from dataclasses import dataclass
@dataclass
class Product: ...
```

```python
import dataclasses
@dataclasses.dataclass
class Product: ...
```

第一种名字短，第二种能一眼看出来源。本项目多使用第一种。

实际代码还有：

```python
from __future__ import annotations
```

- `__future__`：Python提供未来语言行为的特殊模块。
- `annotations`：让类型标注延后处理，便于类在定义内部引用自己，也减少部分导入时问题。
- 两边双下划线是名字的一部分，不是引号。

## 3. 函数定义：`def`、参数和返回类型

实际函数签名：

```python
def build_product_search_body(
    *,
    keyword: str | None = None,
    min_price: float | None = None,
    max_price: float | None = None,
    category: str | None = None,
) -> dict[str, Any]:
```

逐行解释：

### `def build_product_search_body(`

- `def`：define，定义一个函数。
- `build_product_search_body`：函数名，意思是“构建产品搜索请求体”。
- 名字可以由作者设计，但测试和其他模块已经按这个名字调用后，它就成为接口合同，不能只改定义而不改调用方。
- `(`：函数参数列表开始。

### 单独一行的 `*,`

- `*`之后的参数只能用“参数名=值”的方式传入。
- 因此应写：

```python
build_product_search_body(keyword="phone", min_price=0)
```

- 不能写成难以辨认的：

```python
build_product_search_body("phone", 0)
```

### `keyword: str | None = None,`

- `keyword`：参数名。
- `:`：这里引出类型标注，不是开始字典，也不是要求后面写`{}`。
- `str`：字符串类型。
- `|`：在类型标注中表示“或者”。
- `None`：没有提供值。
- `=`：设置默认值。
- 这一行整体表示：keyword可以是字符串，也可以没有；没传时默认没有。
- 结尾`,`分隔下一个参数。

### `) -> dict[str, Any]:`

- `)`：参数列表结束。
- `->`：标注返回值类型。
- `dict[str, Any]`：返回字典；键是字符串，值结构可以不同。
- 最后的`:`：表示函数体即将在下一行缩进开始。
- Python使用缩进划分代码块，不在`:`后面写Java/C++式大括号。

## 4. 字典、列表和“键”

实际代码：

```python
must: list[dict[str, Any]] = []
filters: list[dict[str, Any]] = []
```

- `must`、`filters`：变量名，由本文件作者选择。
- `:`后是变量类型提示。
- `list[...]`：列表，按顺序保存多个元素。
- `dict[str, Any]`：列表中的每个元素是字典。
- `=`：把右边的值赋给左边变量。
- `[]`：创建空列表。

列表与字典不要混淆：

```python
products = [product1, product2]       # 列表，用整数位置读取
product = {"name": "稳健理财"}      # 字典，用键读取
```

读取：

```python
products[0]         # 第一件产品
product["name"]    # name键对应的值
```

`"name"`这个键在自己设计新字典时可以取别名；但一旦mapping、数据、测试和调用方约定为`name`，就不能只改其中一处。

## 5. `if`与`is not None`

实际代码：

```python
if min_price is not None:
    price_range["gte"] = min_price
```

逐词解释：

- `if`：如果后面的条件为真，就执行缩进代码。
- `min_price`：当前传入的最低价格。
- `is`：判断是不是同一个特殊对象。
- `not`：取反。
- `None`：表示没有值的唯一对象。
- `:`：条件结束，下一行缩进属于该条件。
- `price_range["gte"]`：在字典中写入`gte`这个键。
- `gte`：greater than or equal，大于等于。

为什么不写：

```python
if min_price:
```

因为Python会把`0`、空字符串、空列表当作假。最低价0元是合法输入，不能被误认为“没传”。

相关校验：

```python
if min_price is not None and max_price is not None and min_price > max_price:
    raise ValueError("min_price 不能大于 max_price")
```

- `and`：三个条件必须全真。
- `>`：左边数值大于右边。
- `raise`：主动抛出异常，中止当前正常流程。
- `ValueError`：值的类型可能正确，但值本身不符合合同。

## 6. `append`：向列表末尾追加

实际代码：

```python
filters.append({"range": {"price": price_range}})
```

从内向外读：

1. `price_range`可能是`{"gte": 0, "lte": 5000}`。
2. `{"price": price_range}`变成`{"price": {"gte": 0, "lte": 5000}}`。
3. 再包一层`range`，表示ES范围查询。
4. `filters.append(...)`把这个字典追加到列表末尾。

`append`只接收一个对象。它会修改原列表，返回值是`None`。因此不要写：

```python
filters = filters.append(...)  # 错：filters会变成None
```

## 7. Elasticsearch查询字典

实际返回结构：

```python
return {
    "query": {"bool": {"must": must, "filter": filters}},
    "size": 10,
    "sort": [{"_score": {"order": "desc"}}],
    "highlight": {
        "pre_tags": ["<em>"],
        "post_tags": ["</em>"],
        "fields": {"name": {}},
    },
}
```

### `return`

- 把结果交回调用者，并结束当前函数。
- `print`只是显示；`return`才允许其他代码继续使用这个字典。

### `must`

- 存放必须匹配且参与相关度的关键词查询。
- 有关键词时，本项目加入：

```python
{"match": {"name": {"query": cleaned_keyword}}}
```

- 没有关键词时加入`match_all`，让价格或品类仍可单独过滤所有文档。

### `filter`

- 存放价格和品类等硬条件。
- 它们不需要影响BM25分数。

### `size`

- 当前页最多返回10条。
- 总命中数仍从响应的`hits.total.value`读取，不等于`len(items)`。

### `_score`

- ES计算的相关度分数。
- `desc`是descending，降序，即高分在前。

### `highlight`

- `pre_tags`：命中词前插入`<em>`。
- `post_tags`：命中词后插入`</em>`。
- `fields`：指定对`name`字段高亮。

## 8. 类与对象：为什么用`dataclass`

实际代码：

```python
@dataclass(frozen=True, slots=True)
class Customer:
    customer_id: str
    name: str
    risk_level: str
    available_amount: int
```

- `@`：应用装饰器。
- `dataclass(...)`：根据字段自动生成初始化等方法。
- `frozen=True`：对象创建后不允许普通赋值修改字段，避免流程中误改画像。
- `slots=True`：限制允许的属性名，拼错时更早暴露。
- `class`：定义一种对象模板。
- `Customer`：类名按惯例使用大驼峰。

创建对象：

```python
customer = Customer("C001", "张三", "R1", 5000)
```

读取属性使用点号：

```python
customer.risk_level
```

对象不是字典，不能默认写`customer["risk_level"]`。

示例五把一条ES命中转换成：

```python
@dataclass(frozen=True, slots=True)
class ProductSearchHit:
    product_id: int
    name: str
    highlighted_name: str
    category: str
    price: float
    stock: int
    score: float
```

这里保留`name`和`highlighted_name`两个字段：前者是原始名称，后者是展示用的带`<em>`标签名称。`score`是ES相关度，不是产品收益率，也不能直接当作金融适配结果。

示例数据使用`phone model 001`而不是`phone_model_001`。标准分词器可以稳定把空格分开的`phone`识别为独立词；下划线连接的整串可能成为一个词元，导致`match: phone`没有命中。`price`和命令行上下界均为`float`，所以`100.5`是合法输入。

初始化不是“索引存在就覆盖”。它先读取mapping类型，再只读检查既有文档ID；出现未知ID或合同不一致就抛出`RuntimeError`并保留现场。只有合同属于本项目时才按1～100稳定ID写入，写后再次逐项校验100条完整数据。

## 9. `_source`与`get`

实际搜索响应处理：

```python
source: dict[str, Any] = hit.get("_source", {})
highlighted_values = hit.get("highlight", {}).get("name", [])
highlighted_name = (
    str(highlighted_values[0])
    if highlighted_values
    else str(source.get("name", ""))
)
```

### `_source`

- ES命中的原始文档字段。
- 前导下划线是ES元字段命名，不表示Python私有变量。

### `dict.get(key, default)`

- 找到键：返回对应值。
- 找不到键：返回default，不抛`KeyError`。

连续读取从左到右：

```python
hit.get("highlight", {})
```

先得到高亮字典；如果没有则得到空字典。再：

```python
.get("name", [])
```

取name高亮片段；没有则得到空列表。

### 条件表达式

```python
A if condition else B
```

条件真选A，假选B。此处有高亮就取第一段，否则用原名称。

## 10. `for`循环：逐条处理命中

实际代码：

```python
items: list[ProductSearchHit] = []
for hit in raw_hits.get("hits", []):
    source = hit.get("_source", {})
    items.append(ProductSearchHit(...))
return ProductSearchResponse(total=total, items=tuple(items))
```

- `for`：循环。
- `hit`：当前这一轮的临时变量名。
- `in`：从右边可迭代对象中依次取值。
- 末尾`:`后，缩进区域属于循环。
- 循环结束后才执行与`for`同级的`return`。
- `tuple(items)`把可变列表转换为元组，表达响应结果不应被随意追加。

## 11. Redis缓存键：为什么先读最新画像

实际代码：

```python
cache_key = build_cache_key(
    customer.customer_id,
    question,
    self._data_version,
    profile_fingerprint=_profile_fingerprint(customer),
    catalog_fingerprint=_catalog_fingerprint(self._products),
)
```

逐步运行：

1. `get_customer()`必须先取得最新`risk_level`和`available_amount`。
2. `_profile_fingerprint(customer)`按当前源码生成例如`张三|R1|5000`的画像指纹，依次包含姓名、风险等级和可用金额。
3. `_catalog_fingerprint(...)`把产品名称、风险、起投、状态和说明排序后做SHA-256摘要。
4. `normalize_question()`用NFKC、`strip()`、`casefold()`和空白压缩规范问题。
5. `build_cache_key()`把问题、画像指纹和目录指纹作为摘要材料。
6. 客户编号与`data_version`也进入最终键。

原问题不直接进入键，减少在运维界面暴露完整问题的风险。客户风险、金额或产品状态变化时，指纹变化，旧推荐不会命中。TTL只是过期机制，不能替代画像与目录指纹。

## 12. Redis TTL和`ex`

实际代码：

```python
self._client.set(key, value, ex=ttl_seconds)
```

- `self`：当前RedisTextCache对象。
- `._client`：构造对象时保存的真实Redis客户端。
- `.set(...)`：执行Redis SET。
- `key`：缓存键。
- `value`：JSON字符串。
- `ex=ttl_seconds`：同一条命令设置秒级过期时间。

先SET再EXPIRE有中间失败窗口；用`ex`一次完成更稳妥。TTL到期只让缓存失效，不会删除ES或Neo4j事实数据。

## 13. `Protocol`：只约定“会什么”

实际代码：

```python
class TextCache(Protocol):
    def get(self, key: str) -> str | None: ...
    def set(self, key: str, value: str, ttl_seconds: int) -> None: ...
```

- `Protocol`：结构化接口合同。
- 流水线不关心对象是不是Redis类，只关心它是否有兼容的`get`和`set`。
- `...`是省略号对象，表示这里只声明接口，不提供实际逻辑。
- 因此`InMemoryTTLCache`和`RedisTextCache`都能传给pipeline。

这叫依赖倒置的简单形式：核心业务依赖小接口，而不是绑定某个数据库实现。

## 14. Cypher参数化查询

实际代码：

```python
CUSTOMER_PROFILE_QUERY = """
MATCH (c:Day37Customer {customer_id: $customer_id, dataset_id: '项目'})
RETURN c.customer_id AS customer_id,
       c.name AS name,
       c.risk_level AS risk_level,
       toInteger(c.available_amount) AS available_amount
LIMIT 1
""".strip()
```

逐词解释：

- `MATCH`：匹配图模式。
- `(c:Day37Customer ...)`：变量`c`代表标签为Day37Customer的节点。
- `{...}`：节点属性条件映射。
- `customer_id: $customer_id`：左边是节点属性，右边`$customer_id`是参数占位符。
- `dataset_id: 'day37'`：限制只读取本项目数据。
- `RETURN`：返回字段。
- `AS`：给返回列起别名。
- `toInteger`：将属性转为整数。
- `LIMIT 1`：最多一行。

参数值通过驱动单独传入：

```python
records, _, _ = self._driver.execute_query(
    CUSTOMER_PROFILE_QUERY,
    customer_id=customer_id,
    database_=self._database,
)
```

不要写：

```python
query = f"MATCH (c {{customer_id:'{customer_id}'}}) RETURN c"
```

后一种会让输入改变查询语法，产生引号错误和注入风险。

## 15. RRF：为什么按排名融合

实际核心：

```python
for rank, hit in enumerate(hits, start=1):
    scores[hit.source_id] = scores.get(hit.source_id, 0.0) + 1.0 / (k + rank)
```

- `enumerate`：循环时同时提供序号和值。
- `start=1`：第一条的rank为1，不是0。
- `scores.get(id, 0.0)`：以前没出现时从0分开始。
- `+= 1/(k+rank)`：名次越靠前，贡献越大。

ES的BM25分数和Neo4j关系权重含义不同，直接相加会让某个数值尺度较大的系统支配结果。RRF只用各列表内部名次，降低量纲差异影响。

## 15.1 问题分类与失败时拒答

实际代码定义三种枚举：

```python
class QueryIntent(StrEnum):
    RECOMMENDATION = "recommendation"
    PRODUCT_FACT = "product_fact"
    OUT_OF_SCOPE = "out_of_scope"
```

- `StrEnum`：成员既是枚举值，也具有字符串值，避免到处散落拼写不同的裸字符串。
- `RECOMMENDATION`：出现“推荐、适合、可以买、选择什么”等明确推荐词。
- `PRODUCT_FACT`：问题包含产品名、产品编号、品类或“风险、起投、特点”等银行事实词。
- `OUT_OF_SCOPE`：没有银行领域证据，例如天气问题。

```python
intent = classify_query(question, products)
if intent is QueryIntent.OUT_OF_SCOPE:
    return self._answer_generator.generate(question, customer, [], intent=intent)
```

领域外问题在检索和缓存之前直接拒答，返回空来源和空产品ID。这条门是确定性安全控制，不只是一句提示词。

事实问答与推荐的关键差别：

- 事实问答可以说明某产品“风险R1、起投1000元、有什么特点”，但`recommended_product_ids`保持空；
- 推荐必须结合最新客户画像并执行状态、风险、金额硬过滤；
- 事实存在不代表产品适合当前客户。

## 16. 硬过滤

实际代码：

```python
if product.status.upper() != ACTIVE_STATUS:
    reasons.append("产品当前不在售")
if risk_rank(product.risk_level) > risk_rank(customer.risk_level):
    reasons.append("产品风险高于客户风险承受等级")
if product.min_investment > customer.available_amount:
    reasons.append("客户可用金额低于产品起投金额")
return EligibilityDecision(allowed=not reasons, reasons=tuple(reasons))
```

- 使用三个独立`if`，不是`elif`，因为一个产品可能同时违反多条规则，需要收集全部原因。
- `not reasons`：空列表是假，取反后为真，表示没有拒绝原因。
- `tuple(reasons)`：将原因冻结成元组。

## 17. 缓存命中为什么仍要做安全复核

实际代码：

```python
cached_answer = Answer.from_dict(json.loads(cached_json))
if self._cached_answer_is_safe(cached_answer, customer, intent):
    return replace(cached_answer, cache_hit=True)
```

- `json.loads`：JSON字符串变成Python字典。
- `Answer.from_dict`：字典恢复成Answer对象。
- 损坏JSON或字段缺失会被捕获，不能让坏缓存拖垮主流程。
- `_cached_answer_is_safe`：推荐类缓存中的每个产品仍必须存在，并再次通过当前状态、风险和金额规则。
- 事实问答缓存不得携带推荐产品ID。
- Answer是`frozen=True`，不能直接写`cached_answer.cache_hit = True`。
- `replace`复制一个新对象，只把`cache_hit`改为真。

## 18. LangChain Runnable

实际代码：

```python
def as_runnable(self) -> RunnableLambda:
    return RunnableLambda(
        lambda payload: self.ask(
            customer_id=str(payload["customer_id"]),
            question=str(payload["question"]),
            top_k=int(payload.get("top_k", 5)),
        )
    )
```

- `RunnableLambda`：把普通Python可调用逻辑包装成LangChain统一Runnable。
- `lambda payload:`：定义一个短小匿名函数，输入叫payload。
- `payload["customer_id"]`：必填键，缺失会报错。
- `payload.get("top_k", 5)`：可选键，没传时默认5。
- 包装后可使用Runnable的统一`invoke`接口，也便于以后组成更长的链。

运行模型：

```text
payload字典
→ RunnableLambda.invoke(payload)
→ lambda取字段
→ self.ask(...)
→ Answer
```

Runnable只负责统一调用形式，不会自动增加金融安全。安全来自`ask()`内部不可跳过的硬规则。

## 18.1 FastAPI的`X-API-Key`

实际核心：

```python
configured_api_key = api_key if api_key is not None else os.getenv("DAY37_API_KEY")
api_key_header = APIKeyHeader(name="X-API-Key", auto_error=False)

def require_api_key(provided_key: str | None = Security(api_key_header)) -> None:
    if not configured_api_key:
        raise HTTPException(status_code=503, detail="服务端尚未配置 DAY37_API_KEY")
    if provided_key is None or not compare_digest(provided_key, configured_api_key):
        raise HTTPException(status_code=401, detail="缺少或错误的 X-API-Key")
```

- `os.getenv(...)`：只从当前进程环境读取，不读取或输出`.env`。
- `APIKeyHeader`：告诉FastAPI从`X-API-Key`请求头取值。
- `auto_error=False`：缺失时先得到`None`，由本项目统一返回401。
- `Security(...)`：把请求头解析结果注入函数。
- `compare_digest`：以更稳定的比较方式检查密钥，避免直接字符串比较的部分时序差异。
- 服务端根本没有配置密钥时返回503并失败关闭，而不是允许匿名访问。
- 应用级`dependencies=[Depends(require_api_key)]`让`/health`、`/products/search`和`/qa/ask`全部受保护。

真实密钥不属于源码。只在启动服务的PowerShell中设置`DAY37_API_KEY`，请求端仅从同名环境变量构造头。

## 18.2 为什么数据库地址默认是`127.0.0.1`

Compose把VM宿主端口绑定为`127.0.0.1:端口:容器端口`，外部Windows不能直接访问。`scripts/06_启动SSH隧道.ps1`创建四条`ssh -L`本地转发，使Windows的`127.0.0.1`安全通向VM的回环端口。`Settings`因此默认连接：

```text
ES       http://127.0.0.1:19200
Redis    127.0.0.1:6380
Neo4j    bolt://127.0.0.1:7689
```

`scripts/07_停止SSH隧道.ps1`只依据本项目状态文件和完整命令行合同停止登记的ssh进程，不杀其他SSH会话。

## 19. 完整`ask()`调用顺序

阅读`pipeline.py`时按下面编号写在代码旁：

1. 检查question、customer_id长度和top_k。
2. 根据customer_id从Neo4j/仓库读取**最新Customer**。
3. 用确定性词表分类为推荐、产品事实或领域外。
4. 领域外立即拒答，不输出产品或来源。
5. 计算客户画像指纹与产品目录指纹，再构造缓存键。
6. 缓存命中时解析JSON并执行`_cached_answer_is_safe`；安全才返回。
7. 缓存未命中时分别执行ES文本召回和Neo4j图召回。
8. RRF融合两路名次。
9. 事实问答定位明确产品；推荐问答执行状态、风险和金额硬过滤。
10. 回答生成器按intent生成事实、推荐或拒答文本。
11. 将Answer转JSON写缓存并附TTL。
12. 返回Answer。

注意最新画像必须在缓存之前；推荐硬过滤必须在生成之前。顺序变化会分别造成旧画像缓存或违规产品进入回答。

## 20. 三个运行推演

### 场景A：C001第一次问稳健产品

- 先读C001最新画像，生成画像与目录指纹，缓存miss。
- ES与图各返回候选。
- RRF融合。
- C001风险R1、金额5000：P002风险R2被过滤，P003风险R4被过滤，P004风险和金额都不符，P005不在售。
- 仅允许的证据进入回答器。
- 回答写入缓存。

### 场景B：C001立即重复同一问题

- 规范化问题摘要相同。
- 客户画像、目录、问题和版本均相同，缓存key相同。
- 恢复Answer，再复核推荐产品仍合规，最后将`cache_hit`标记为真。

### 场景C：C002问相同问题

- 客户编号不同，缓存key不同。
- 不能命中C001的个性化答案。
- 按C002的R3与20000元重新过滤。

### 场景D：C001金额或风险变化

- 客户编号虽然不变，画像指纹变化。
- 缓存key不同，不能使用旧推荐。
- 用最新画像重新检索、融合和过滤。

### 场景E：询问“安心存款起投金额是多少”

- intent是`PRODUCT_FACT`。
- 返回P001的起投金额和来源，但`recommended_product_ids`为空。
- 这是陈述事实，不表示P001适合客户。

### 场景F：询问“今天天气怎么样”

- intent是`OUT_OF_SCOPE`。
- 返回范围说明，产品ID和来源均为空。
- 不进入产品推荐链。

## 21. 常见错误对照

| 错误写法 | 结果 | 正确理解 |
|---|---|---|
| `if min_price:` | 0元边界丢失 | 判断`is not None` |
| `products["name"]` | 列表不能用字符串键 | 先循环得到单个字典/对象 |
| `filters = filters.append(x)` | filters变成None | 直接`filters.append(x)` |
| `hit["highlight"]` | 没有高亮时报KeyError | `get`并回退_source |
| 缓存键没有画像/目录指纹 | 同一客户变化后读旧推荐 | 先读最新画像并加两种指纹 |
| f-string拼Cypher | 注入和引号风险 | `$参数`单独传值 |
| LLM先生成、后硬过滤 | 违规产品已进入回答 | 先过滤证据再生成 |
| 天气问题也进入图召回 | 无关问题推荐产品 | 领域外意图在检索前拒答 |
