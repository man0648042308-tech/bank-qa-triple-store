# 常见报错与排查

## 0. 先学会保留错误证据

出错时不要只发“运行不了”。至少保存：

```text
1. 当前PowerShell提示符中的完整目录
2. 自己输入的完整命令
3. Traceback第一行
4. Traceback最后一行
5. 修改前后相关代码10行
6. 容器或端口健康检查结果
```

Traceback通常从下往上读：最后一行是错误类型和摘要；再向上找第一个指向自己项目文件的行。

## 1. `ModuleNotFoundError: No module named 'day37_bank_qa'`

### 原因

- 没在项目根目录运行；
- 没有执行`uv sync`；
- 使用了Anaconda的Python，而不是项目虚拟环境。

### 检查与修复

```powershell
Set-Location "./Day37_Bank_QA_Homework"
uv sync --python 3.12
uv run python -c "import day37_bank_qa; print(day37_bank_qa.__file__)"
```

预期打印本项目`src\day37_bank_qa\__init__.py`的路径。

## 2. `Failed to spawn: oython`

这是命令拼写错误：把`python`写成了`oython`。正确命令：

```powershell
uv run python -m pytest -q
```

逐词核对，不要把网页中的反斜杠转义字符或HTML实体一起复制进终端。

## 3. 中文乱码

先保证源码右下角编码是`UTF-8`，按`Ctrl+S`保存，然后在当前PowerShell设置：

```powershell
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

这只作用于当前终端窗口，关闭后需要重新设置。

## 4. `ConnectionError`或`Connection refused`

含义：Python能解析地址，但目标端口没有服务接受连接。按顺序检查：

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\01_检查VM.ps1"
powershell -ExecutionPolicy Bypass -File ".\scripts\06_启动SSH隧道.ps1"
powershell -ExecutionPolicy Bypass -File ".\scripts\03_健康检查.ps1"
```

不要立刻修改Python。先确认：VM是否开机、身份是否匹配、Docker是否运行、容器是否健康、VM端口是否只绑定回环、SSH隧道进程是否存在、本机`127.0.0.1`转发端口是否可达。Windows Python默认不再直连VM IP。

## 5. SSH连接超时

可能原因：虚拟机未启动、IP变化、VM身份不匹配、VMnet8异常或代理软件改写网络。先运行`01_检查VM.ps1`，保留VMX/身份、Ping、22端口和SSH输出。显式目标验证失败时应停止，不能静默换到另一台可登录Docker主机。不要猜密码，不要把密码写进项目。

## 5.1 VMware Tools未返回IP，但SSH能够连接

2026-09-04真实案例：指定VM已开机，来宾open-vm-tools服务为active，宿主vmrun仍报告installed/Tools未运行。重启来宾工具服务没有恢复上报；这不等于Ubuntu未开机或SSH不可用。

处理：在已核验的本机环境给01～06脚本显式传入 `-VmIp "192.168.220.77"`。脚本会保留精确VMX运行检查，并追加SSH严格主机指纹与VMX/来宾UUID比对。UUID不符、SSH失败或输入非法IP都必须拒绝。不可删除身份检查或通过扫描网段猜另一台主机。

离线回归：`powershell -NoProfile -ExecutionPolicy Bypass -File "./Day37_Bank_QA_Homework\tests\verify_vm_identity.ps1"`，预期 `VM_IDENTITY_TEST_PASS cases=9`。`-NoProfile`表示不加载个人终端启动配置；其余参数解释见复现手册第5.2节。

## 6. Elasticsearch显示黄色状态

单节点本地验证环境若配置了副本，副本无法分配，状态可能是yellow。先查看索引副本配置；技术演示单节点可设`number_of_replicas: 0`。生产环境不能机械照抄。

## 7. Elasticsearch中文搜索没有命中

依次检查：

1. 产品文档是否已导入；
2. 查的是否是正确索引；
3. `name`字段mapping；
4. 分词结果；
5. 实际查询体；
6. 是否被价格或品类filter排除。

本项目不把版本不匹配的IK插件强装进ES。不要用IK `8.6.2`配ES服务端`8.18.0`；本项目Python客户端锁定`8.18.1`，依赖合同为`>=8.18,<8.19`。

## 7.1 `RuntimeError`或“已有索引合同不符”

这不是让你删除索引的提示，而是安全拒绝：同名索引的mapping、文档ID、文档数量、字段、值或类型与示例合同不一致。保留完整错误与索引只读信息，先确认它是不是旧项目或他人数据。禁止为了通过验收直接删除未知索引。

## 8. 高亮字段不存在或`KeyError: 'highlight'`

不是每条命中都保证有高亮。错误写法：

```python
hit["highlight"]["name"][0]
```

思路是先用`get`提供默认值，再回退到`_source`中的原名称。具体实现见`exercise05/search_products.py`。

## 9. 价格为0却没有加入范围条件

若写：

```python
if min_price:
```

`0`会被Python视为假。可选数值参数要判断“有没有传”：

```python
if min_price is not None:
```

## 10. Redis第二次仍然未命中

检查：

- 第一次回答后是否真的执行写入；
- 两次的客户编号、最新画像指纹、问题文本和数据版本是否完全一致；
- TTL是否已经到期；
- 两次是否连接同一个Redis数据库；
- 序列化或反序列化是否报错。

不要为了“命中”而删除客户或画像维度，否则会产生串答案或画像变化后返回旧推荐的风险。风险等级或金额变化时，本来就应该miss。

## 11. Redis中出现永久键

先检查TTL：

```text
TTL返回 -1：键存在但没有过期时间
TTL返回 -2：键不存在
TTL返回正数：剩余秒数
```

写入时应使用原子的“值 + 过期时间”操作。发现永久示例缓存时，只能清理本项目明确前缀的键，禁止执行`FLUSHALL`。

## 12. Neo4j认证失败

错误可能类似`Neo.ClientError.Security.Unauthorized`。检查连接地址、用户名、运行配置与容器日志。不要把真实密码粘贴到聊天、源码或Markdown；只确认配置来源是否存在。

## 13. Cypher查询没有结果

按顺序检查：

1. 初始化脚本是否执行；
2. `Customer`、`Product`标签拼写；
3. `customer_id`属性名和值；
4. 关系方向；
5. 参数字典的键是否和`$customer_id`一致。

变量名可以自己取，但标签、属性名和参数名属于调用合同，必须与数据和代码一致。

## 14. `TypeError: '>=' not supported between instances of 'int' and 'str'`

比较双方类型不一致。例如客户金额是整数，产品起投金额却是字符串。优先在数据模型入口统一类型，不要在每次比较时到处临时转换。

## 15. FastAPI启动后网页打不开

先确认终端没有退出，再访问：

```text
http://127.0.0.1:8000/docs
```

若8000端口被占用，可临时换成8001，但要记录实际端口。数据库在VM，不代表FastAPI也在VM；本项目API默认运行在Windows本机。

## 15.1 FastAPI返回401

401表示API鉴权失败。先确认当前启动服务的PowerShell和发请求的PowerShell都使用同一个临时密钥：

```powershell
$headers = @{ "X-API-Key" = $env:DAY37_API_KEY }
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health" -Headers $headers
```

- 没有`DAY37_API_KEY`：先在启动服务前用`Read-Host`输入临时值；
- 请求头缺失或拼成别的名字：必须401；
- 值错误：必须401；
- 正确值：才应200。

不要把真实值直接写在`.ps1`、Markdown、截图、聊天或提交包中。

## 15.2 天气问题却返回产品

这是问答边界错误，不是正常推荐。无关问题必须返回拒答文字、空`recommended_product_ids`和空来源。修复后运行无关问题负向测试，再回归事实问答与推荐，不能只改提示词。

## 16. 停止服务时担心删除旧数据

先停本项目SSH隧道，再按需停止容器：

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\07_停止SSH隧道.ps1"
powershell -ExecutionPolicy Bypass -File ".\scripts\05_停止Day37.ps1"
```

不要自行执行`docker system prune`、`docker volume prune`、`docker compose down -v`。停止容器不等于删除数据卷；是否删除是另一项高风险操作。
